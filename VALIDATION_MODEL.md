# docbridge — validation model, v0.2.4

How every verdict in a report is reached, and where a PASS can still be wrong.
Code references are to `src/docbridge/`. Written 2026-09-25, revised 2026-09-27.

## 1. The principle

A result is the number, the control that had to pass first, and the sentence saying
what it does not show (METHODOLOGY, "the one sentence"). Applied here:

- **Every axis states its `scope`.** A PASS covers that sentence and nothing else.
- **UNKNOWN is never a finding** (METHODOLOGY R1, R19). Content docbridge cannot read
  becomes a *sentinel* token that equals nothing — not even another sentinel. No
  comparison can pass across it, and a difference touching it is `unverifiable`: it can
  stop an axis from passing, it can never make it fail.
- **Protection is declared as a domain, not enumerated as failures** (R19). Every token
  containing a number character is compared, whatever its shape. Shape classes (date,
  currency, ...) only label differences.
- **The converter is not the checker** (R7). Pandoc converts Markdown↔DOCX; docbridge's
  own readers judge the result (§8).

## 2. The canonical form (`canonical.py`)

Every extractor produces the same shape: an ordered list of **blocks** (paragraph,
heading, list item, table cell, code, quote, note, furniture, text box, unreadable),
each an ordered list of **segments**. Every segment has an **origin**:

| Origin | What it is |
|---|---|
| `content` | ordinary visible text |
| `list_label` | an ordinal label a numbering engine renders: `1.`, `a)`, `1.2.` |
| `image_alt` | an image's alternative text |
| `note_ref` | a footnote/endnote reference, rendered `[n]` |
| `note` | a footnote/endnote body, placed after the main text |
| `ruby` | DOCX ruby guide text (`w:rt`), the small text Word shows above its base text; read after the base |
| `furniture` | page headers and footers |
| `unknown` | present but unreadable → a sentinel |

Origins exist because formats disagree about what is text. A DOCX list label is
generated by numbering definitions; the same `1.` in a PDF is a literal character. Both
are text here, tagged, so each comparison can include or exclude a class **for a
format pair** instead of guessing (§6).

## 3. Normalization — the declared domain (`normalize.py`)

Applied identically to both sides, in this order:

1. Unicode **NFC** (again per token, so a combining mark split from its letter across
   DOCX runs still composes).
2. Four invisible characters removed: **U+00AD** soft hyphen, **U+200B** zero-width
   space, **U+2060** word joiner, **U+FEFF** zero-width no-break space.
3. Seven ligatures expanded: **U+FB00–U+FB06** (ff, fi, fl, ffi, ffl, ſt, st).
4. List-bullet glyphs removed: **U+2022 U+25E6 U+25AA U+2023 U+2043 U+2219** and the
   Symbol/Wingdings Private Use points **U+F0B7 U+F0A7 U+F0D8 U+F076**. Checkbox glyphs
   (☐ ☒) are **not** bullets: a box changing state is data.
5. A **token** is a maximal run of characters for which `str.isspace()` is false.
   `tests/test_normalize.py` proves the tokenizer's `\S+` equals `str.split()` for every
   Unicode code point.

**Nothing else is folded**: not case, not quotes, not dashes, not digits of other
scripts. A straight quote turning curly is a difference.

## 4. The three token views (`compare.py`)

| View | Membership | Compared as |
|---|---|---|
| `text` | every token | the full token |
| `numeric` | every token containing a Unicode **N\*** character (decimal digits in any script, superscripts, fractions, roman-numeral letters) | the token's *core*: sentence punctuation stripped from its edges — openers `( [ { < " ' « “ ‘ „ ‚ ‹`, closers `) ] } > " ' » ” ’ › , ; : . ! ? …`. `-`, `−`, `+`, `%`, currency symbols are kept. |
| `identifier` | tokens whose core has an identifier class (below), space-grouped numbers, numbers beside a currency word, plus hyperlink targets | the core, or the grouped value |

Identifier classes describe **shape, never meaning**: `url`, `email`, `date`
(`d/m/y`, `y-m-d`, `d.m.y` shapes), `time` (`hh:mm`), `percentage`, `currency` (a
currency symbol in the token, or a declared currency word next to it: NOK EUR USD GBP
SEK DKK ISK CHF JPY CNY PLN CZK HUF CAD AUD kr kr. Kr Kr. € $ £ ¥), `long_number` (≥ 6 digits),
`grouped_number` (`923 456 781`, `4 999`, `48 750,00`: a 1–3 digit head, 3-digit groups,
optionally a decimal part on the last), `code` (letters and digits, e.g. `NO93`,
`INV-2025-0042`), `filename` (`name.ext`). A 9-digit number is labelled
`long_number`, never "organisation number".

The identifier view is a **pure function of the token sequence**: grouping runs break
only at sentinels, never at block boundaries. (The property fuzz found the earlier
per-block grouping turning a line break into an identifier FAIL — §11.)

**Links.** Markdown links, raw-HTML `<a href>` links (inline, in HTML blocks, in table
cells and in captions — the destination is the `href` attribute as lxml's HTML parser reads
it, never a pattern match), DOCX hyperlinks and hyperlink fields, and PDF URI annotations. A hyperlink target is compared
only if it is not visible in its own link text (an autolink or pasted URL is already
covered by the text view). `mailto:` is stripped.
Compared as an ordered list, inside the identifier axis, only when both formats carry
links (§7).

## 5. Alignment

Each view is aligned as a **sequence** (`difflib.SequenceMatcher`, `autojunk=False`,
common prefix and suffix trimmed first). Order matters: two amounts swapped between
table cells keep the set of numbers identical and are still a FAIL.

- `equal` spans produce nothing (text view: a token matched on a different page is
  counted for `structure.pages`).
- A span containing a sentinel → one `unverifiable` difference; the axis cannot PASS.
- Otherwise: text view → one difference per span; numeric/identifier views → one per
  token (`changed` pairwise, the rest `missing`/`added`); a value missing in one place and
  added in another is paired as `moved`.
- Axis status: any difference between readable values → **FAIL**; only unverifiable
  spans → **NOT_CHECKED** (`unresolved_content`); nothing → **PASS**. Zero tokens on both
  sides → PASS with `compared: 0` (and, for numbers, `vacuous: true`), so "nothing to
  compare" is distinguishable from "compared and equal" (R1).
- A differing region over 250,000 tokens → NOT_CHECKED (`too_large`).

## 6. What a comparison includes, per format pair

| Origin | Included when |
|---|---|
| `content`, `list_label`, `ruby` | always |
| `image_alt` | both formats are Markdown or DOCX |
| `note_ref`, `note` | neither format is PDF |
| `furniture` | never |
| `unknown` | always (sentinels cannot be projected away) |

What is excluded is counted per side (segments and characters) in
`axes.text.details.excluded_from_comparison` and listed in `unsupported_checks` (R18).

## 7. Structure checks

Each check first consults the capability matrix (`contract.CAPABILITIES`):

| | TXT | Markdown | DOCX | PDF |
|---|---|---|---|---|
| headings | no | yes | yes | no |
| lists | no | yes | yes | no |
| tables | no | yes | yes | no |
| links | no | yes | yes | yes |
| emphasis | no | yes | yes | no |
| pages | no | docbridge markers | layout | yes |
| image alt text | no | yes | yes | no |

Both "yes" → compared. Source has it, target cannot → UNSUPPORTED (`absent_in_format`,
with the source count). Source lacks it, target has some → NOT_CHECKED
(`inferred_structure`). Neither → UNSUPPORTED.

| Check | Compares |
|---|---|
| `pages` | page count, and that every matched token is on the same page number. DOCX vs a paged format → NOT_CHECKED (`needs_layout_engine`). |
| `headings` | (level, text) in order |
| `lists` | (depth, ordered/bullet) per item in order; labels and item text belong to the text view. A list item is one wherever it sits — body, table cell, nested table, text box, footnote, or a heading that carries numbering — and keeps its other role too (v0.2.4, audit W2); headers and footers are never compared |
| `tables` | count, rows × columns, every anchor cell's (row, col, rowspan, colspan, text) |
| `emphasis` | the text of every bold span, and of every italic span, in order. Direct and character-style formatting only; paragraph-style formatting (a bold heading style) is not emphasis. |

**An incomplete inventory is not a verified one** (v0.2.3, audit N1). When a reader sees
structure of a check's kind that it reads as text but does not model, it records the place
(`Canonical.structure_unknown`), and that check cannot pass: a comparison that would have
been PASS is NOT_CHECKED (`unresolved_content`), with `details.unmodelled_source`,
`unmodelled_target` and the first places named. A difference between the items it did model
is still a FAIL. Recorded by the Markdown reader: a heading, list or table tag inside a
paragraph (one inline tag cannot say what it contains), a table inside an HTML table cell
(flattened into the cell), content in an HTML table outside every cell, and any HTML
element outside the declared domain (which gaps all four checks). Recorded by the DOCX reader
(v0.2.4, audit W1): a table nested in a table cell, at any depth — its text is read into the
outer cell, its own rows, cells and spans are not compared.

## 8. Reading rules per format — the oracles

| Format | Reader | What "the document says" means |
|---|---|---|
| TXT | docbridge | lines; UTF-8 or UTF-16-with-BOM, otherwise the caller names the encoding |
| Markdown | markdown-it-py 4.2.0, `commonmark` preset + tables + strikethrough | the text a CommonMark renderer shows. Ordered labels render as CommonMark does (start number + position); a typed number that never renders is warned (`md_list_number_not_rendered`). Raw HTML — blocks, table cells, captions and inline tags — is read by **one reader over one declared domain** (`extract/html.py`), parsed by lxml, **in document order**: the text of a declared list of block and inline elements; **structure as the Markdown syntax would give it** (v0.2.3, audit N1) — `<h1>`–`<h6>` headings with their level, `<strong>`/`<b>` bold and `<em>`/`<i>` italic as emphasis spans (one per paragraph, as in DOCX), `<ul>`/`<ol>`/`<li>` list items with depth and ordered/bulleted — in blocks, cells, captions and, for emphasis, inline tags alike, so the same structure written as Markdown or as HTML compares equal; `<a href>` links with the parsed attribute; `<img alt>` as image alt text; `<br>`; `<ol>` numbered from `start` (any `type`, `reversed` or `<li value>` → sentinel); tables read where they stand — caption first, then cells, with rowspan/colspan, a table in a cell flattened into it, anything in a table outside every cell and caption → sentinel; `script`, `style`, `template`, `head`, `title` and comments not rendered; **every other element** (svg, math, iframe, object, embed, canvas, video, audio, form and its controls, base, custom elements) → sentinel, with or without text. `<!-- docbridge:page N -->` sets pages; `<!-- docbridge:unreadable-page N ... -->` is a sentinel; both are read from parsed comments, never by pattern over the raw HTML. |
| DOCX | docbridge over lxml (`extract/docx.py`) | the document as if every tracked change were accepted: `w:ins`/`w:moveTo` kept, `w:del`/`w:moveFrom` dropped; field *results* read, instructions skipped; content controls read; `mc:AlternateContent` read through `mc:Choice` only (Fallback repeats the same text box); `w:vanish` hidden runs excluded and counted; a paragraph's numbering resolved as ECMA-376 17.3.1.19/17.9.23 say — its own `numPr` overrides its style's property by property (a paragraph may give only the level), `numId` 0 ends numbering, and a list that comes from the style takes the level linked to that style (`w:lvl/w:pStyle`, nearest style first) — and a numbered paragraph is a list item in every context, keeping its cell, text-box, note or heading role (v0.2.4); list labels computed from `numbering.xml` (decimal, decimalZero, letters, roman; bullets are markers) — a num with a `startOverride` keeps its own counters, nums sharing an abstractNum otherwise continue one sequence, numbering a level restarts deeper levels, an omitted `w:start` is 0 (ECMA-376); any other number format, equations (anywhere: in a paragraph, directly in the body, in a table cell, a content control or any wrapper), charts, SmartArt and every other non-picture graphic, OLE objects, ActiveX controls, ink (`w:contentPart`), subdocuments (`w:subDoc`), legacy check-box and drop-down form fields, altChunk and date/page elements → sentinels; text a drawing holds outside its text boxes → sentinel; an unrecognised element of any vocabulary holding Word, Office Math or DrawingML text (or a WordArt text path) → sentinel; ruby (`w:ruby`): the base text, then the guide text as origin `ruby`; VML WordArt (`v:textpath/@string`) is read like a text box; footnotes/endnotes render `[n]` in reference order; headers/footers are furniture; `wp:docPr/@descr` is image alt text. Strict Open XML, `.docm`, `.dotx` are refused. |
| PDF | PyMuPDF 1.27.2.3 | the **text layer** in content-stream order — not the rendered glyphs. Per page: `present`, `absent` (something is drawn but there is no text → sentinel, OCR required) or `blank` (nothing drawn at 24 dpi). Pages with raster images over 5% of the area, invisible text (usually an OCR layer), repaired files and permission-encrypted files are warned. |

**Independence (R7).** For Markdown↔DOCX the converter (Pandoc) and both readers
(markdown-it-py, lxml) are independent; a converter bug must coincide with a reader bug
to pass silently. They share the *dialect* on purpose: Pandoc runs as
`commonmark+pipe_tables+strikeout`, the dialect the reader parses, because Pandoc's `gfm`
reader was measured rewriting content the reader keeps literal (`:smile:` → 😄,
`- [ ]` → ☐). **For PDF → Markdown the converter and the checker share PyMuPDF's text
layer**: a PASS there means "the Markdown preserves what PyMuPDF reads from the text
layer". A wrong ToUnicode map would be wrong on both sides — measured: one TTF font
round-tripped `·` (U+00B7) as `ꞏ` (U+A78F), and PDFium read the same wrong character, so
a second PDF engine is not an independent oracle either. That check was therefore not
built.

## 9. Page operations (`convert/pdf_ops.py`)

Merge and split copy page objects, so the question is identity. Output page *k* is
compared **positionally** with the one source page it must have come from — never
searched for — so a dropped, duplicated or reordered page cannot hide and blank pages
cannot be confused:

- `layout`: the page rendered at `raster_dpi` is pixel-identical (SHA-256 of the samples).
  MuPDF renders both sides; this proves the page content survived the copy, not that
  MuPDF renders correctly.
- `structure.page_identity`: identical text layer. `page_rotation`, `page_size`,
  `page_links`, `page_annotations`, `page_form_fields`: identical values/counts.
- `structure.bookmarks`: level, title, page **and destination** — the linked page and
  position, URL, file or named action — equal the sources' bookmarks concatenated (merge) or
  cut to the range (split), pages shifted, levels clamped to start at 1. The expectation is
  derived from the source files' complete bookmarks, never from the converter's own list.
  Visual state (collapsed, colour, bold/italic) is not compared. In a split, a bookmark whose
  page is outside every range, or that has no page (a URL), is in no output and is reported
  as `bookmarks_not_carried`.
- The text/numeric/identifier axes also run, over the concatenated sources.

## 10. Images (`convert/images.py`)

| Input | Embedded as |
|---|---|
| JPEG | the original bytes (DCTDecode). EXIF orientation and requested rotation are applied by the placement matrix. |
| PNG, 8-bit, no transparency | handed to MuPDF, stored decoded and lossless |
| anything with transparency | colour and alpha split by Pillow, both embedded as lossless PNG (alpha as the soft mask) — MuPDF's own PNG import premultiplies: (10,20,30, α40) was stored as (12,19,31) |
| TIFF/BMP/GIF/WEBP (single frame), mirrored EXIF orientations | decoded once, embedded as lossless PNG, reported as a transformation |
| 16-bit, multi-frame, non-JPEG CMYK | refused |

The `image` axis per page (v0.2.3, audit N2–N4 — §17) — what the page shows, compared
exactly with the source:

- **The planned construction.** The page dictionary holds exactly `Type`, `MediaBox`,
  `Rotate`, `Resources`, `Parent`, `Contents` (no annotations, transparency group or crop;
  the effective CropBox is the MediaBox); the resources hold exactly one image; the content
  is `q <matrix> cm /<image> Do Q` and nothing else (no other drawing, graphics-state
  transparency, blend mode or clip); the image and soft-mask dictionaries hold only the
  planned keys (no `/Mask`, `/ImageMask`, `/SMaskInData`, `/OC`, `/Intent`, `/Interpolate`,
  `/Matte`, ...), and `/Decode` appears only on a JPEG. Measured 2026-09-26 on every input
  kind: this is what the builder writes; anything else can change what the page shows.
- **Bytes or samples.** A JPEG: the stored stream, read raw, equals the file byte for byte,
  under exactly `/DCTDecode` with no `/DecodeParms`, with the JPEG's own size at 8 bits, and
  `/Decode [1 0 1 0 1 0 1 0]` exactly when it is an Adobe CMYK JPEG (the case MuPDF writes)
  and absent otherwise. Anything else: the stored samples, decoded by MuPDF (so a `/Decode`
  array is applied), equal the source's **compared as RGB** — the source's colour kept, a
  gray output widened, never the source narrowed to what the output holds; an image that
  carries transparency of its own (a colour key, a stencil) is a difference.
- **Colour space.** The samples are read in the source's own ICC profile when it has one for
  its channel count, otherwise in MuPDF's default profile (read from MuPDF itself) or the
  device space it stands for. Identical samples in another colour space are other colours.
- **Effective opacity.** The soft mask — fully opaque when there is none — equals the
  source's alpha, a source without alpha being fully opaque; added, removed or changed
  transparency is a difference.

Orientation, two measurements (v0.2.2, audit K2 — §16):

- **Geometry, exact.** The image's drawing matrix is read back from the PDF
  (`get_image_info`). It must be a rotation by a multiple of 90° (page `/Rotate`
  included; clockwise angle = atan2(b, a) in PyMuPDF's y-down space, measured on 0/90/180/270),
  not mirrored (determinant > 0), not skewed, filling the planned rectangle; and the stored
  pixels turned by that angle must equal the expected upright image, pixel for pixel.
- **Visual, in colour.** The image region is rendered near native resolution (≤1024 px);
  it and the expected upright image are reduced to ≤64 px **by the same Pillow box filter**;
  PASS if the mean absolute error over R, G and B is ≤ 16/255 and no other rotation matches
  better. A CMYK image is converted to RGB by MuPDF's converter on the expected side too —
  the renderer's own conversion, one conversion for both sides.

Either measurement finding a difference → FAIL. The geometry matching → verified. The
geometry unreadable → the visual measurement decides only if it **discriminates** (another
rotation is measurably worse); otherwise the page is NOT_CHECKED (`inconclusive`), never
PASS. The per-page row keeps `verdict`, `discriminating`, `mae_expected`, `mae_best_other`
and adds `geometry` and `visual`; `discriminating` now means the verdict rests on a
measurement able to tell the rotations apart (inside `visual`: the expected rotation and the
best other one differ by more than 1/255, in either direction). (Earlier instruments disagreed with
themselves: MuPDF's colour-managed gray vs Pillow's luma differed by ~23 levels on
(200,30,30); two different resampling filters misread noise images as wrongly rotated; and
MuPDF's CMYK→RGB conversion differs from Pillow's by a colour MAE of 33.7.)

## 12. Known false alarms (FAIL or NOT_CHECKED where the documents agree)

Safe in direction — never a false PASS — but they cost trust:

- PDF reading order differs from the logical order (multi-column layouts, tables whose
  cells are drawn column by column).
- Line-end hyphenation in a PDF (`impor-` / `tant`) is compared literally.
- A number wrapped across two PDF text blocks, or across a page break.
- DOCX → PDF made by Word: footnotes (excluded, but their marks and bodies are PDF text),
  headers/footers (PDF text, never in the DOCX stream), Word's level-2 bullet `o`,
  numbering formats outside decimal/letters/roman (sentinels).
- Pandoc drops raw HTML blocks when writing DOCX: `markdown_to_docx` reports their text
  missing (correctly — it is lost).
- An UNKNOWN construct next to a real change makes that span `unverifiable`: the axis is
  NOT_CHECKED rather than FAIL there.
- Raw HTML outside the declared domain (§8) makes every comparison of that file NOT_CHECKED,
  even with itself. HTML text a browser may hide — a closed `<details>`, `<noscript>`,
  `<rp>`, CSS-hidden text — is read anyway: more text than a browser shows, never less.
- Structure docbridge reads but does not model (§7) makes that structure check NOT_CHECKED
  even when both documents hold the same thing.
- *(Repaired in 0.2.3, audit N4: every CMYK JPEG in `images_to_pdf` reported a false image
  FAIL, because the byte check read PyMuPDF's `extract_image`, which re-encodes CMYK. The raw
  stream is read now — §10.)*

## 13. Blind spots — where a PASS can still hide a change

- **PDF text layer ≠ page.** Text drawn as outlines, text inside raster images (a scanned
  signature page inside a text PDF), and wrong ToUnicode maps are invisible. Pages with
  images and invisible text are warned; nothing is claimed about them.
- **Formatting beyond bold/italic** (font, size, colour, underline, alignment,
  typography) is not compared: `layout` is NOT_CHECKED or UNSUPPORTED for document
  conversions.
- **Headers/footers, comments, images** are never compared in document conversions
  (counted in `unsupported_checks`).
- **Hidden text** is excluded on the DOCX side; a conversion that reveals it shows as added
  text, one that hides visible text shows as missing text — but hidden-on-both-sides is
  never examined.
- **DOCX numbering** follows the rules in §8. They are declared, not verified against
  Word's own rendering.
- **Normalization folds four invisible characters, seven ligatures and ten bullet glyphs.**
  A change that only adds or removes those is invisible by declaration.
- **HTML attributes other than `href` and `alt`** (tooltips, `data-*`, `cite`), CSS, and
  the quotation marks a `<q>` adds are not compared.
- *(Repaired in 0.2.4, audit W1/W2 — §18: a nested DOCX table's shape change and a list
  removed from a DOCX cell or text box used to pass.)*
- **DOCX headings and emphasis inside footnotes — found by the round-4 coverage review
  (2026-09-27), repaired 2026-09-28:** removing bold inside a
  footnote passed (emphasis 0 against 0), and a footnote heading changed from level 1 to
  level 2 passed (headings 0 against 0). Now bold and italic in footnotes and endnotes are
  emphasis, so that change FAILs, and a faithful DOCX→Markdown conversion with bold in a
  footnote no longer false-FAILs (1 against 2 before). A heading inside a note is read but not
  modelled, since Markdown cannot carry one: the headings check reports NOT_CHECKED
  (`unresolved_content`) whenever one exists, even for an identical copy, never PASS.

## 14. Lossless reading (`reading.py`, v0.2)

**Invariant:** docbridge may reduce the volume of its own responses, but it never alters,
summarizes, paraphrases, semantically filters, or silently truncates source evidence.
Reading is exact retrieval; nothing in the path decides what is relevant.

**The reading text.** Each document is a list of units: PDF pages (each page's text layer
exactly as PyMuPDF returns it), TXT/Markdown lines (the decoded file, CRLF/CR → LF only;
Markdown as source, not rendered), DOCX paragraphs (as the §8 reader extracts them, with
`⟦UNREADABLE: reason⟧`, `⟦image alt: …⟧` and `⟦ruby: …⟧` marking what is not plain body
text). The
reading text is the units joined by one newline; every offset, cursor and `match_id`
indexes it. Cursors and match ids carry a 16-hex key derived from the file's SHA-256 **and**
the reading text's SHA-256, so they are refused against a changed file and against a
different decoding of the same file (the same bytes decoded differently are different text);
an ASCII file that decodes identically either way keeps its references valid.

**Reads.** An excerpt is `reading_text[char_start:char_end]`, returned with the SHA-256 of
its UTF-8 bytes, the units it spans and each unit's start offset. If the requested range is
longer than `max_chars`, the excerpt stops there, `truncated` is true, `remaining_chars`
says how much is left and `next_cursor` continues at exactly the next character. Following
cursors to the end rebuilds the range exactly (property-tested: `tests/test_reading.py` R1,
on every fixture format and on randomly generated text, with odd caps such as 101 and 137).
`unreadable_units` lists the unreadable units inside the excerpt — an empty unit at the end
of the range counts — and `range_unreadable_units` lists every unreadable unit of the whole
requested range, whether or not this excerpt reached it.

**Read-around.** The excerpt always contains the match. When the requested surrounding
units exceed the cap, the window is placed around the match and both sides left out are
stated — `omitted_before_chars` with a `before_cursor`, `remaining_chars` with a
`next_cursor` — so the whole requested range stays reachable (R5 rebuilds it).

**Search.** A literal query's whitespace matches any whitespace run, so a phrase broken
across lines or pages is found. Query and text are folded identically: composed (NFC)
segment by segment, cutting only before a character whose canonical decomposition starts
with a starter that never composes with what precedes it (the Unicode normalization
boundary, UAX #15; ICU's hasCompBoundaryBefore) — so every canonically equivalent form
matches: a decomposed "café" and a composed one, Hangul jamo and syllables, Bengali and
Tamil two-part vowels; then the four removed invisible characters and the seven ligatures
of §3; and case unless `case_sensitive`. Each folded character maps back to its segment, so
a match returns exact original offsets (property-tested: the fold equals whole-string NFC
on generated text from every composition class). Nothing else is folded: a digit or letter
changed in the query does not match. A literal query reports every occurrence, overlapping
ones included; a regex reports leftmost non-overlapping matches. Matches are returned
verbatim with their context (R4: a literal search for any span of any fixture finds it at
its offset — the corpus includes decomposed text since audit F4).

**Time bound.** Every search — literal or regex — runs in a separate process
(`_search_worker.py`, standard library only) that is killed after
`DOCBRIDGE_SEARCH_TIMEOUT_S` seconds (default 2; measured: `(a+)+$` on 101 characters stops
at 2.11 s; a literal search of a one-line file took 47 ms including the process start). A stopped search
returns `search_timeout` and no result — never a partial or empty one, because an empty
answer would read as absence.

**Where a read can still mislead.**

- The PDF reading text is the text layer (§8, §13): outlined text, text inside images and
  wrong ToUnicode maps are invisible to reads and searches alike. Pages without a text layer
  are listed as `unreadable_units`/`unsearchable_units`; pages with raster images are named in
  search notes. **Zero matches is not evidence of absence** on those pages, and every
  search response says so when they exist.
- DOCX has no plain text to quote, so a DOCX excerpt is docbridge's extraction, not source
  bytes: tracked changes accepted, hidden text excluded, list labels rendered by §8's
  numbering rules.
- `document_outline` shows only what the file encodes. An untagged PDF without bookmarks
  has no headings in its outline; that is the file, not a finding.
